Acceptance criteria:
- With no selected location in production app state, `OxygenApp` shows a first-run manual location selection surface instead of `HomeScreen` backed by `SampleWeather.bundle`.
- The first-run surface offers manual search entry and a separate "Use my location" action.
- Editing/submitting the manual search path does not request Android location permission, does not create/select a `WeatherLocation`, does not route Home, and does not claim geocoding success.
- Manual search submission retains the submitted query and shows a visible non-success message that location search is not connected yet in Slice 9.
- A provider-neutral location-permission request command is emitted only after the explicit "Use my location" action.
- If permission is denied or unavailable through the production app permission-result callback boundary, app state returns to or remains on manual selection with a visible provider-neutral message that location permission is optional and the user can search for a place instead.
- No hidden default location, hard-coded location, scaffold location, or sample `WeatherBundle` is used to satisfy Home success when no location has been selected.
- Provider DTOs and provider IDs do not cross into app UI state or Composables.
- Existing scaffold sample weather may remain available only as explicitly marked preview/scaffold data outside the no-selected-location production path.
Acceptance boundary: Slice 9 is complete when focused app tests prove the same production state holder used by `OxygenApp` resolves no-selected-location app state to first-run manual-selection presentation state rather than sample Home state; UI-level evidence proves default `OxygenApp()` renders the first-run manual selection controls and not sample Home content; default `MainActivity -> OxygenApp()` startup enters that no-selected-location route and the production `OxygenApp` default path does not import or pass `SampleWeather.bundle`; manual query editing/submission retains the submitted query, shows a visible "location search is not connected yet" non-success message, does not emit a location-permission command, does not create/select a `WeatherLocation`, does not route Home, does not show loading/searching/results/empty-result UI, and does not claim geocoding success; the explicit "Use my location" action emits a provider-neutral permission-request command that `OxygenApp` drains into a root permission-request callback; denied/unavailable permission state is reachable through a production app permission-result callback and returns to manual selection with a visible optional-location message; and default production routing cannot satisfy Home success using `SampleWeather.bundle` or a hidden/default location. This slice does not verify the Android OS permission dialog, acquire device location, perform geocoding, select a result, route to Home, fetch forecasts, persist locations, or perform live provider calls.
